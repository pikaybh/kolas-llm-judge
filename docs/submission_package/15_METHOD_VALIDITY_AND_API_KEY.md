# 비교행렬 기반 위험요인 식별 성능시험의 목적 적합성 설명

- KOLAS-DOC-015 / 2026-10-27 / 시험기관 협의용
- 대상: SEEXR 위험성평가 AI
- 제안 주지표: Hazard Identification Accuracy (HIA)
- 실행 환경: Blue 운영 API (`https://api.seexr.co.kr/api`)
- 기존 425개 시나리오와 843개 연구실 검증 GT는 변경 없음

## 1. 왜 비교행렬인가?

건설 안전의 위험요인은 동일한 현상을 다양한 자연어 문장으로 설명할 수 있다. 시험하려는 기능은 정답 문구의 복사 여부가 아니라 **작업 환경에서 관리해야 할 위험의 식별 여부**다. 단순한 문자열 비교는 이 의미적 동등성을 측정하기 어렵다.

본 방법은 GT 위험요인 전체와 AI 생성 위험요인 전체의 쌍을 비교한다. Judge는 위험 발생 메커니즘(H), 작업·노출 맥락(C), 사고 또는 피해 메커니즘(A)을 개별 이진 판정하며, **사전에 정한 Boolean 식으로만 결과를 집계**한다. 모든 쌍별 판단과 원문이 대응되므로 뒤에서 감사·재계산할 수 있다.

해당 방식은 한국인공지능검증원이 요구한 **유효성, 객관성, 재현성, 추적성**을 확보하기 위한 기술적 근거를 갖는다. 그러나 이 논증만으로 KOLAS 시험방법으로 승인됐다고 할 수 없으며 시험기관과 사전에 판정기준을 확정해야 한다.

## 2. 제안하는 측정식

시나리오 s의 기준 위험요인 `r_si`와 AI 생성 위험요인 `g_sj`에 대해:

```text
H_sij = 1  위험 발생 메커니즘이 동등
C_sij = 1  작업·설비·노출 맥락이 양립
A_sij = 1  사고 또는 피해 메커니즘이 실질적으로 양립

M_sij = (H_sij AND C_sij) OR A_sij
I_si  = max_j(M_sij),  생성 결과가 없는 경우 I_si = 0

HIA_evaluable (%) = 100 × Σ_(r∈E) I_r / |E|
HIA_end_to_end(%) = 100 × Σ_(r∈T) 1[r∈E]·I_r / |T|
```

E: 정상적인 비교행렬 평가가 끝난 기준 위험요인. T: 시험 선정 GT 전체. 한 GT를 여러 AI 출력이 설명하더라도 **GT 기준 식별 성공은 최대 1건**으로 집계한다.

사고분류 레이블만 같다는 뜻으로 A를 자동 True 처리하는 것이 아니라, 사전에 정의된 사고·피해 메커니즘의 의미적 양립성 판단을 사용한다. 이러한 해석범위는 기존 judge rubric과 사전 통제문항에 근거하며, 시험기관과 합의해야 한다.

## 3. 시험기관 요구사항에 대응

| 요구사항 | 구현·검증 증거 |
|---|---|
| 유효성 | 작업상 동일 또는 양립 가능한 위험을 식별했다는 안전공학적 측정목적 |
| 객관성 | 3개 Boolean 항목, 동일한 공식, 사전 지정된 시나리오/GT |
| 재현성 | Judge 모델·프롬프트·설정 고정, 같은 입력의 독립 반복, AJQG 통제문항 |
| 추적성 | 시나리오·GT·생성결과·Judge 쌍별 판정·run ID 연결 |
| GT 적정성 | 연구실이 기존에 검증한 GT 843개 유지, ID/출처/수정이력 관리 |
| Judge 적격성 | 사전에 정한 104개 AJQG 통제문항 및 반복 판정의 안정성 기록 |
| 오류 처리 | SUT 미완료와 평가기/인프라 장애를 구분하고 재시험 정책을 적용 |
| 독립성 | 평가 원본과 Judge 결과를 분리 저장, 제출 전 자료·판정기준 확정 |

추가적인 독립 건설안전 전문가 2인의 새로운 재판정은 **이번 계획에 포함하지 않는다**. 이것이 시험기관에서 요구하는 최소한의 Judge 판정 검증을 충족하는지는 문의·확인을 받는다. 이미 수행하지 않은 검증을 완료된 사실로 기술하지 않는다.

## 4. 과거 개발시험의 측정결과(유지)

| 지표 | 계산 | 기존 기록 |
|---|---|---|
| 넓은 HIA, 평가완료 기준 | 795/831 | **95.67%** |
| 엄격 의미 판정, 진단용 | 711/831 | 85.56% |
| 엄격 1:1 대응, 진단용 | 704/831 | 84.72% |
| 넓은 HIA, 전체 GT 기준 | 795/843 | 94.31% |
| 시나리오 완료율 | 419/425 | 98.59% |

**이 표는 기존 개발시험 관측값이다.** 공인시험의 결과나 최종 합격 판정이 아니다. 831개와 843개의 분모 차이는 이전 실행에서 시나리오 6개에 대한 정상 평가가 완료되지 않아 GT 12개가 비교행렬 평가대상에서 제외됐기 때문이다. 한 측정량을 다른 측정량으로 호칭하거나 실패를 숨기지 않는다.

넓은 HIA를 **공식 주지표 후보로 우선 제안**하고, 분모·합격기준·재시험 처리조건은 시험기관의 사전 승인 대상으로 표시한다.

## 5. 시험기관에 제안하는 확정사항

1. Hazard Identification Accuracy를 해당 건설 위험요인 식별 성능시험의 **주지표**로 인정할지.
2. 위험 발생 메커니즘과 작업 맥락뿐 아니라 실질적인 사고·피해 메커니즘의 양립성을 인정하는 `(H∧C)∨A` 판정기준이 타당한지.
3. 정상 평가된 위험요인 기준의 HIA와 전체 시험대상 GT 기준의 지표를 성적서에서 어떻게 구분하고 어느 것을 합격기준에 적용할지.
4. 기존 연구실 GT 검증과 AJQG 통제항목·반복안정성 기록이 Judge 적격성 설명으로 충분한지.
5. 실행 반복 횟수, 오류/비응답 분류, Judge 모델·설정과 SUT 운영 릴리스의 고정 범위.

## 6. 실행과 기술기록

시험기관이 사용할 API 주소는 `https://api.seexr.co.kr/api` **하나**다. API 키는 SEEXR 담당자가 별도로 전달한다. 시험기관은 수령한 `SEEXR_API_KEY`를 요청의 `x-api-key`에 설정하며 별도 로그인 과정은 없다. Judge에는 독립된 `OPENAI_API_KEY`를 사용한다.

요청·응답·결과·판정 로그와 데이터셋/모델/실행기 버전은 시험기록으로 관리하되 **키 원문을 문서나 로그에 포함하지 않는다**. 파일의 SHA-256은 제출 자료의 변경 여부를 추적하기 위한 무결성 식별정보일 뿐 자료의 암호화 또는 성능의 증명으로 설명하지 않는다.

현재 Blue 배포 및 운영용 API 키 준비가 완료되지 않았으므로, 이 문서의 URL은 **시험 대상 환경 제안**이며 실제 시험 개시 가능 여부는 별도 확인한다. 실제 실행방법: `11_API_ACCESS_GUIDE.md`.
